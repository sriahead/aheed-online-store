# Platform costs, competitor pricing, profitability and business models (validation)

> **Testing Strategy (Lean 80/20 Model)**
> Provide enough testing to give confidence without creating unnecessary or duplicate tests. Avoid testing the same behaviour multiple times at different levels unless doing so provides additional confidence.
>
> **The Main Principle:**
> - **Build:** Did we build the component correctly?
> - **Validate:** Does the feature work correctly in the real system?
> - **Release:** Is the complete system safe, reliable, and ready for users?

## Testing Areas

Every feature should have appropriate **Unit** and **Integration** testing, followed by relevant validation testing. Broader testing mainly happens before release. However, testing is risk-based: features involving auth, payments, UI changes, performance-sensitive APIs, databases, or external dependencies require additional relevant testing earlier.

1. **Unit Testing**: every feature. Isolated business logic, utilities, components.
2. **Integration Testing**: every feature. The component with its immediate dependencies.
3. **System / End-to-End Testing**: critical journeys and validation.
4. **Regression & Acceptance Testing**: before release or when core flows change.
5. **Performance & Resilience Testing**: before release or for performance-sensitive APIs.
6. **Security & Accessibility Testing**: before release, earlier for auth, payments or UI changes.

This slice touches auth (a platform-admin gate on a new route and two new actions), an external
dependency (Workers AI and outbound fetches of third-party pages), and a migration, so the access,
injection and allow-list checks below are not optional.

## Setup (for the live rows R38 and R39)

1. Read CLAUDE.md "Config & secrets". Check `DIRECT_URL` and `DATABASE_URL` **one at a time** (a
   per-variable loop with `printenv "$v" >/dev/null 2>&1`, printing the host only) and confirm
   `.dev.vars` names the **dev** Neon host. If either variable is exported, prefix every Prisma
   command with `env -u DIRECT_URL -u DATABASE_URL`.
2. Apply the R21 migration to **dev**. Per memory and CLAUDE.md, auto mode blocks
   `prisma migrate deploy`, so hand the user
   `! env -u DIRECT_URL -u DATABASE_URL npx prisma migrate deploy`. First read the datasource host
   from `npx prisma migrate status`, and confirm it is the dev host. Then run `npm run db:generate`.
3. `npm run preview` and wait for `Ready on http://127.0.0.1:8787`.
4. Send every request to `http://127.0.0.1:8787` with `-H "Host: localhost:8787"`,
   `-H "Origin: http://localhost:8787"` and `-H "x-forwarded-proto: http"`. Prefix curl with
   `MSYS_NO_PATHCONV=1` in Git Bash, and never use `-o /dev/null`. Sign in with a cookie jar to
   `/api/auth/sign-in/email` as `demo-admin@example.com` (platform admin),
   `demo-store-admin@example.com` (vendor ADMIN) and `demo-staff@example.com` (vendor STAFF). The
   shared demo password is in the seed notes. Never write it into a spec or a commit. On a `429`,
   wait about 30 seconds and retry.
5. When finished, kill the whole `node`/`workerd` chain and confirm none remain.
