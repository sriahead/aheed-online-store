# Dedicated Cell Isolation: Aheed Food Centre Deployment Topology & CI (requirements)

Context: Closes #1331 (Parent: #1337, Workstream P12-B). Builds on `specs/architecture.md` ("Cells"), ADR-004 (multi-tenancy), and the Cloudflare for SaaS onboarding runbook (#1476). Establishes dedicated cell deployment topology, separate database isolation in Neon for Aheed Food Centre, lockstep CI deployment across platform and client cells, and database bootstrap tooling.

R1. Root `wrangler.toml` declares dedicated environment blocks `[env.afc-staging]` and `[env.afc-production]`, each specifying `name = "afc-store-staging"` and `name = "afc-store-production"`, dedicated R2 image bucket bindings (`afc-images-staging` and `afc-images-production`), custom domain routes (`staging.aheedfoodcentre.co.uk` and `www.aheedfoodcentre.co.uk`), dedicated KV `JOB_SIGNALS` namespaces, and environment variables including `PLATFORM_NAME = "Aheed Food Centre"`.
R2. `workers/scheduler/wrangler.toml` declares dedicated environment blocks `[env.afc-staging]` and `[env.afc-production]`, each specifying `name = "afc-scheduler-staging"` and `name = "afc-scheduler-production"`, Cron triggers, dedicated KV `JOB_SIGNALS` bindings, and `APP_BASE_URL` pointing to `https://staging.aheedfoodcentre.co.uk` and `https://www.aheedfoodcentre.co.uk`.
R3. `workers/inbound-email/wrangler.toml` declares dedicated environment blocks `[env.afc-staging]` and `[env.afc-production]`, each specifying `name = "afc-inbound-email-staging"` and `name = "afc-inbound-email"`, and `APP_BASE_URL` pointing to `https://staging.aheedfoodcentre.co.uk` and `https://www.aheedfoodcentre.co.uk`.
R4. `.github/workflows/deploy-staging.yml` compiles Next.js once via OpenNext, applies migrations sequentially to `DIRECT_URL` (Platform) and `AFC_DIRECT_URL` (Dedicated Cell), verifies routes for staging and afc-staging, and deploys both platform and AFC workers (`staging` then `afc-staging`), schedulers, and inbound-email workers.
R5. `.github/workflows/deploy-production.yml` applies migrations sequentially to both production databases (`DIRECT_URL` and `AFC_DIRECT_URL`), verifies routes for production and afc-production, and deploys both platform and AFC workers (`production` then `afc-production`), schedulers, and inbound-email workers.
R6. `scripts/verify-worker-routes.ts` accepts `--env afc-staging` and `--env afc-production`, matching declared routes in `wrangler.toml` against `VendorDomain` rows in the targeted AFC database.
R7. A standalone script `scripts/bootstrap-dedicated-cell.ts` exists to bootstrap a freshly migrated AFC database with the canonical `Vendor` row (`a4ed0000-0000-4000-a000-000000000001`), domain mappings, and initial store configuration (`VendorConfig`, delivery slots, delivery areas), while strictly refusing to insert demo accounts in production.
R8. Unit tests in `tests/dedicated-cell-topology.test.ts` verify that `wrangler.toml`, `workers/scheduler/wrangler.toml`, and `workers/inbound-email/wrangler.toml` define conforming `afc-staging` and `afc-production` environments, correct bucket bindings, and custom domain route coverage.
R9. Unit tests in `tests/bootstrap-dedicated-cell.test.ts` verify that `scripts/bootstrap-dedicated-cell.ts` validates parameters, safely injects the vendor entity, configures domain routing, and blocks demo accounts on production targets.
R10. `specs/architecture.md` and ADR-009 (`specs/decisions/ADR-009-dedicated-client-cells.md`) record the platform cell plus dedicated client cells topology, runtime isolation rationale, and lockstep CI deployment.
R11. `docs/developer-portal/env-setup.md` documents the `AFC_*` secret requirements for staging and production, including the checklist for dedicated cell onboarding.
R12. `CHANGELOG.md` updated under `[Unreleased]` (Gate 4).
R13. `npm run lint`, `npm run typecheck`, `npm run format:check`, `npm run kms:validate`, `npm run kms:check-generated`, and `npx vitest run --maxWorkers=4` all pass (Gate 3 catch-all).
