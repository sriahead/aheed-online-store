# P7b — UK GDPR data-subject rights (validation)

**Before starting, confirm which database is in play.** `npm run preview` reads `.dev.vars`;
`prisma migrate`, `db:seed` and any `tsx` script read `.env`. Diff both against
`secrets/staging.vars` **and** `secrets/production.vars` before running anything here — two files
drifting into agreement on the *wrong* target is how P5a's migration reached production
(CLAUDE.md, #119). Every row below expects **staging**.

Rows R10–R21 need a two-vendor fixture: one `User` with orders, an address, a review, a cart, a
loyalty account with ledger entries and a discount redemption at **both** Aheed and SriMart on
staging. `scripts/verify-data-rights.ts` (added by this slice) creates it, snapshots every affected
row, runs the operation under test and diffs the result, so the before/after comparisons below are
mechanical rather than eyeballed.

| R1  | `npx tsx --eval "import('./lib/repositories/data-rights.ts').then(m => { const ns = m.default ?? m; console.log(Object.keys(ns).sort().join(',')); })"` prints a list including `countOtherVendorData`, `eraseVendorData` and `exportPersonalData`. **The `m.default ?? m` and the explicit `.ts` both matter**: this repo has no `"type": "module"`, so tsx transpiles the eval to CJS and `import()` hands back an interop wrapper whose only key is `default`.
