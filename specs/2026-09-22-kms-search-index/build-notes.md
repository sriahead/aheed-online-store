# KMS internal docs site — build the Pagefind search index (build notes)

Written at the end of Build, **before** the Clear. Closes `#871` (search index) and `#857`
(assembled-content `.gitignore` rule). Branch `feature/871-kms-search-index`, two commits:
`875ddab` (spec) and `f4efd83` (build).

## What changed and why

**The defect, restated so the validating context does not have to reconstruct it.** Nextra 4 loads
its search index at runtime as a dynamic import of `/_pagefind/pagefind.js`
(`nextra/dist/client/components/search.js:13`). Nothing in this repository had ever produced that
file — `pagefind` was not a dependency, there was no `public/` directory in `kms/site-internal`,
and the string `pagefind` appeared nowhere outside `node_modules`. So the asset 404'd and the
client threw `TypeError: Failed to fetch dynamically imported module` on every query. Search had
never worked since the site went live, while `lint`, `typecheck`, `test`, `build`, `gates`,
`deploy-docs-internal` and `sdd:audit` all stayed green.

**Five files carry the fix.**

- `kms/site-internal/package.json` — `pagefind` at an exact `1.5.2`, and a `postbuild` running
  `pagefind --site .next/server/app --output-path public/_pagefind && node scripts/verify-search-index.mjs`.
  `postbuild` rather than a workflow step because `opennextjs-cloudflare build` shells out to
  `npm run build` (`@opennextjs/aws/dist/build/buildNextApp.js:10-17`), so the hook fires *inside*
  the OpenNext sequence, and `createStaticAssets()` collects `public/` *after* that
  (`@opennextjs/cloudflare/dist/cli/build/build.js:63` vs `:80`). One hook therefore covers
  `npm run build`, `npm run preview`, `npm run deploy` and the CI workflow without touching any of
  them — the workflow file is unchanged.
- `kms/site-internal/scripts/verify-search-index.mjs` — **the reason this slice is worth more than
  a one-line script.** `pagefind` exits 0 when it walks a directory containing no matching HTML, so
  a postbuild that merely *runs* the indexer reproduces the same class of silent failure one layer
  down: a wrong `--site` path yields an empty index and a still-broken search box, with a green
  build. The guard asserts the **output**: the loader exists and is non-empty, and
  `pagefind-entry.json` reports more than zero pages summed across languages.
- `.gitignore` — two changes in the one `# KMS` block. `public/_pagefind/` is ignored (generated,
  ~245 files, ~3.3 MB). And `#857`: `kms/site-*/content/*/*.mdx` matched exactly one level under
  `content/`, correct until `#853` moved assembled content to `content/<track>/<type>/`, after
  which it silently stopped matching anything `assemble.ts` writes. Now depth-agnostic
  (`content/**/*.mdx`) with the `index.mdx` negation widened to match.
- `kms/site-internal/README.md` — a "Search does not work under `npm run dev`" section (that is
  Nextra's documented behaviour, not a bug, and the next reader will otherwise file it as one),
  plus the `content/dev/*.mdx` path corrected to `content/<track>/<type>/*.mdx`. That path was
  stale from the same `#853` move as `#857` itself.
- `ARTIFACT_INDEX.md` and `app/(admin)/staff/runbook/docs.ts` — regenerated by
  `npm run kms:build-index`; 195 → **196** artifacts, the one new row being this slice's own
  `plan.md`.

## Decisions taken during the build

- **Exact pin `1.5.2`, against the surrounding caret ranges.** The binary generates both the index
  *and* the `pagefind.js` that reads it, so a floating minor silently changes a shipped build
  artifact. Deliberately **not** added to `tests/dependency-pins.test.ts`: that test exists for the
  three *runtime infrastructure* packages `CLAUDE.md` names, which fail silently at request time.
  A wrong `pagefind` fails the build loudly, which the guard already covers. The pin here is a
  reviewable convention, not a mechanically enforced one — recorded so a later reader sees a
  decision rather than an oversight.
- **A plain `.mjs` guard, not a test.** `kms/site-internal` has no test runner and no `tsx`; a guard
  needing its own toolchain is one that gets deleted the first time it is inconvenient. Node
  builtins only.
- **The guard sums `page_count` across languages** rather than reading `languages.en`, so it keeps
  working if the corpus ever stops being English-only.
- **`git check-ignore -v` as the `#857` proof, not "nothing shows in `git status`".** Absence can be
  produced by an empty directory, a stale index or a previous `git clean`. The rule-level check
  names the matching `.gitignore` line, and the mirror-image check proves the three hand-authored
  `index.mdx` files are *not* caught by it.
- **The README path fix was folded into `#857`** rather than left or filed separately: it is the
  documentation half of the exact same post-`#853` staleness, inside a file this slice already
  edits.
- **`npm audit` left alone.** `npm install` reported 9 vulnerabilities in `kms/site-internal`
  (`next`, `wrangler`, `miniflare`, `sharp`, `undici`, `nanoid`, `qs`, `@xmldom/xmldom`,
  `speech-rule-engine`). Checked the `via` chains: **none originates from `pagefind`.** All
  pre-existing. `CLAUDE.md` forbids `npm audit fix --force`.

## Deviations from the spec

- **R4's literal count is 198, not the 197 the spec recorded.** Not a defect and not a deviation
  from the requirement, which is written as a formula: indexed = prerendered HTML − pages lacking
  `data-pagefind-body`. Measured at Build as **198 = 200 − 2**. The corpus grew by exactly one page
  between Spec and Build because this slice's own `plan.md` was assembled into it. The two
  exclusions are unchanged (`_not-found.html`, `_global-error.html`). **A validator must re-derive
  the number, not compare against 197 or 198** — adding any document moves it again.
- **R5's end-to-end proof was taken at the `npm run postbuild` level, not a full `npm run build`.**
  Both guard branches were exercised directly (missing loader; a fabricated index reporting
  `page_count: 0`) and both exit 1, and `pagefind` itself was confirmed to exit 1 on a nonexistent
  `--site`. The composed command is what `postbuild` runs, so npm propagates either failure to
  `npm run build`. The full-build form of the deliberate break is R5's validation row and is left
  for `/validate` to execute from a fresh context, which is where it belongs — it costs two
  ~4-minute builds and self-certifying it here would defeat the point of the Clear.
- Nothing else. Gate 4 (`CHANGELOG.md`) is in this stage's commit, per `CLAUDE.md`'s rule that
  Gate 4 lands in `/build-notes`.

## Known-shaky areas

- **Nothing deployed has been verified.** Every check so far is local. R12 (an authenticated
  `GET /_pagefind/pagefind.js` returning 200) and R13 (a real query returning `/dev/` and `/staff/`
  hits) are **owner-executable only** — the site sits behind Cloudflare Access and an
  unauthenticated request cannot reach it. During Orient an unauthenticated `curl` to the docs host
  failed at TLS (exit 35) and to the SriMart staging host returned `000`; neither is evidence about
  the site, and neither should be read as one.
- **The guard protects the deploy, not the pull request.** `gates` never builds the docs site
  (`CLAUDE.md`, Commands), so the guard first runs in `deploy-docs-internal` — *after* merge to
  `staging`. Strictly better than the previous state, where nothing failed at all, but it is not
  PR-time coverage. Tracked as `#872`.
- **Index size is a new ~3.3 MB of Worker static assets**, 245 files, largest 182 KB. Comfortably
  inside Workers' asset limits (20,000 files, 25 MiB each) and **separate from the 3 MB Worker
  *script* limit** that `#865` concerns — do not conflate the two. Not measured against a cold-start
  or bandwidth budget.
- **Three test files fail on this machine and did so before this slice.**
  `tests/concurrency-slot-booking.test.ts`, `tests/express-sla.test.ts`,
  `tests/slot-capacity.test.ts`, all `PrismaClientKnownRequestError`. Confirmed pre-existing by
  stashing this entire change and re-running them — they fail identically. That is **`#797`** (live-DB
  fixtures that never clean up their vendors), not this slice. Full suite:
  **3 failed / 157 passed files, 3 failed / 2122 passed tests.** Do not report this branch as
  "suite green"; it was not green before it either.
- **`kms:check-generated` reads committed content, not the working tree** (the `#861` fix: it
  restores against `git show HEAD:<path>`). Regenerating `ARTIFACT_INDEX.md` and running the check
  *before committing* therefore reports both artefacts stale and exits 1. That is correct
  behaviour, not a regression — commit first, then check. It cost a confused minute here and will
  cost the next reader the same.
- **The `**` glob is broader than the rule it replaced.** It now ignores `.mdx` at *any* depth under
  `kms/site-*/content/`, so a future hand-authored page that is not named `index.mdx` would be
  ignored silently. That is the correct trade today — every non-`index.mdx` file under `content/` is
  generated — but it is the thing to re-examine if someone later adds a hand-written content page.
