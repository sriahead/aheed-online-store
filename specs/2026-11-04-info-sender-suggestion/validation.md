# Client Setup: info- sender suggestion from the store's subdomain (validation)

> **Testing Strategy (Lean 80/20 Model)**
> `suggestSender` is a pure function, so its unit tests are the whole proof of R1–R4. The live check
> is one look at the Client Setup Sender card on staging after deploy (the post-ship sanity check),
> because the hosts there come from real `VendorDomain` rows.

## Validation Steps

| Req | Testing Area | How to verify                                                                                                                                                                                                                                                                                                                 |
| --- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | Unit         | `npx vitest run tests/client-setup-sender-suggestion.test.ts` passes, including the five R1 custom-host cases and "custom host beats a platform subdomain". Each expects an `info@` address.                                                                                                                                  |
| R2  | Unit         | Same run: the R2 cases expect `info-corner@platform.test` for `corner.platform.test`, the canonical host over an alphabetically earlier one, the alphabetical fallback when none is canonical, and a lower-cased label from `Corner.PLATFORM.test`.                                                                         |
